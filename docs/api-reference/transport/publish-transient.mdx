`PublishTransient` · Transport

PublishTransient publishes one transient message. An optional single
StreamSend publishes it as a packet of a transient replay stream instead:
the caller passes the stream id and the phase (start|delta|end), and the SDK
assigns the contiguous replay seq and the issuedAtMs stamp exactly once,
atomically with the stored envelope, and re-sends them unchanged through
RetryPublish. A stream packet requires a connection that negotiated
streamMode=replay_v1 and a store implementing AtomicStreamOutboxStore;
otherwise it fails closed before any frame is written. Transient receipt
semantics are unchanged.

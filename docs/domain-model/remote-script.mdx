title: "远程脚本"
description: "通过 runCommand 在云桌面内执行脚本，管理进程、文件和应用，并获取逐桌面结果。"

远程脚本提供资源内操作系统的执行入口。你可以通过脚本查询系统信息、操作文件、管理进程或启动应用，并读取每台桌面的状态与输出。它使用 `RuntimeManager.runCommand`，无须创建 Agent 会话。

## 认证和目标

当前由 **管理员身份**调用：JS / Go / Java 使用 AK/SK；Node / CLI 也支持[管理员 OAuth 或可续期凭据](/guides/administrator-oauth)。云端仍校验真实资源权限。无影用户态当前返回 UNSUPPORTED，Android / iOS 移动接口没有此入口。

使用明确的真实 `desktopIds` 和 `regionId`，不能用 Runtime ID、Agent ID 或显示名代替。执行用户和权限由部署与云端合同决定，SDK 不隐式提升权限。下例针对支持 PowerShell 的 Windows 桌面；其它脚本类型和系统支持需按实际环境核对。

## 执行第一个脚本

先完成管理员 Client 初始化，下面只保留必要参数。`handleEvent` / `handleError`（Go / Java 的 observer）由宿主按下一节实现：

<CodeGroup>

```ts TypeScript
const runtimeManager = await admin.buildRuntimeManager(ctx);
const subscription = await runtimeManager.runCommand({ timeout: 600_000 }, {
  regionId, desktopIds: [desktopId], type: 'RunPowerShellScript',
  commandContent: 'Get-Process | Select-Object -First 5 ProcessName, Id',
}, { onEvent: handleEvent, onError: handleError });
```

```go Go
runtimeManager, err := admin.BuildRuntimeManager(ctx)
if err != nil { return err }
subscription, err := runtimeManager.RunCommand(ctx, &model.RunCommandRequest{
    RegionID: regionID, DesktopIDs: []string{desktopID}, Type: "RunPowerShellScript",
    CommandContent: "Get-Process | Select-Object -First 5 ProcessName, Id",
}, observer)
```

```java Java
RuntimeManager runtimeManager = admin.buildRuntimeManager(ctx);
RunCommandRequest request = new RunCommandRequest();
request.regionId = regionId;
request.desktopIds = Collections.singletonList(desktopId);
request.type = "RunPowerShellScript";
request.commandContent = "Get-Process | Select-Object -First 5 ProcessName, Id";
RuntimeCommandSubscription subscription = runtimeManager.runCommand(request, observer, ctx)
    .toCompletableFuture().get();
```

```sh CLI
wuying runtimes run-command --profile admin --request-file script.json --timeout 600000 --output jsonl
```

</CodeGroup>

CLI 的 script.json：

```json
{
  "regionId": "cn-hangzhou",
  "desktopIds": ["desktop-id"],
  "type": "RunPowerShellScript",
  "commandContent": "Get-Process | Select-Object -First 5 ProcessName, Id"
}
```

替换为实际已授权的桌面与地域。将 commandContent 换成自己的脚本即可操作系统，例如 `Start-Process notepad.exe` 启动程序。应用是否出现在当前交互桌面取决于实际执行身份和会话；脚本执行成功本身不保证界面可见。需要查看画面或人工操作时，结合 [ASP](/domain-model/asp)；本接口不额外提供截图或鼠标键盘注入 API。

## 处理事件和最终结果

| kind | 宿主如何处理 |
|---|---|
| accepted | 立即保存 receipt：regionId、desktopIds、invokeId、requestId；这表示云端受理 |
| desktop | 用 result 替换对应桌面的状态和 output，不能把它当作增量文本追加；检查 outputTruncated / dropped |
| completed | 读取 results，检查 allSucceeded；完成不等于每台桌面的脚本都成功 |

只有桌面状态 Success 且 exitCode 为字符串 `"0"` 才算成功，缺失退出码不能补零。SDK 自动查询云端执行记录，当前不是服务端主动 Push；接入方无须再建立一套轮询器。

保留 Client 和订阅直到 completed 或 onError。Go / Java 的 ctx 也要覆盖整个观察过程；Java 默认调用期限只有 30 秒，长脚本需显式设置足够期限。`timeoutSeconds` 是云端脚本执行期限，调用 ctx / CLI timeout 是本地观察期限，含义不同。完整字段和预算见 [`runCommand`](/api-reference/runtimes/run-command)。

## 断线后继续读取原结果

取得 invokeId 后，用原回执恢复观察，不重新执行脚本：

<CodeGroup>

```ts TypeScript
const subscription = await runtimeManager.observeCommand({ timeout: 600_000 }, {
  regionId, desktopIds: [desktopId], invokeId,
}, { onEvent: handleEvent, onError: handleError });
```

```sh CLI
wuying runtimes observe-command --profile admin --request-file receipt.json --timeout 600000 --output jsonl
```

</CodeGroup>

receipt.json 只包含原回执的 regionId、desktopIds、invokeId，不是整个 JSONL 输出对象。当前 Client 已关闭时，可先用相同管理员身份创建新 Client 再恢复观察。

提交超时且没有取得 invokeId 时，先核对已授权的云端执行记录，不自动重发脚本。退订、关闭 Client 或中断 CLI 只停止本地观察，不停止已受理的远程命令。

CLI 的 runtime-command 事件位于 JSONL 的 data 中。全部目标成功退出 0；脚本失败退出 5并在 error.details 保留逐桌面结果；超时/未知结果退出 6，认证/授权错误退出 3，中断退出 130。先保留身份和回执再处理恢复，详见 [`observeCommand`](/api-reference/runtimes/observe-command)。

## 与其它云资源能力配合

- [Runtime](/domain-model/02-runtime-agent)：发现环境、管理云桌面生命周期。
- [ASP](/domain-model/asp)：查看并交互操作云桌面画面。
- [端口服务](/domain-model/port-service)：访问资源内提供的服务。
- Agent 任务通过 [Conversation](/domain-model/03-conversation) 发送自然语言；远程脚本直接提交指定脚本内容。

---
title: "跟踪一次写入结果"
description: "为支持的写入保存稳定标识，超时后继续查询同一次操作。"
---

创建或修改业务对象时，请求可能已经到达服务端，但应用在收到结果前超时。此时先核对原操作，避免用新身份重复提交。

仅对明确支持 `MutationOptions` 的方法，在发送前生成并保存 `mutationId`。之后使用该方法返回或合同要求的 `MutationRef`，通过 `getMutation` / `subscribeMutation` 查看原结果。它不是所有接口都支持的通用幂等参数。

| 场景 | 建议处理 |
|---|---|
| 写前本地校验明确失败 | 修正参数，再发起操作 |
| 请求超时、断线，无法确认服务端是否受理 | 保存原身份，先查询或订阅原结果 |
| 返回版本冲突 | 重新读取当前状态，再由应用决定是否修改 |

普通错误对象里的 not_started 可能只是默认值；没有明确的未受理证据时，不能据此生成新 ID 自动重发。消息发送的命令回执另见[超时后查询原结果](/domain-model/command-receipt)。

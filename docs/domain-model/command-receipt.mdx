---
title: "超时后查询原结果"
description: "通过原消息命令的回执确认受理情况，再核对真实执行结果。"
---

应用发送了一条消息，却因网络断开没有收到响应。这并不能说明发送失败，也不能据此立即再发一条。

消息请求发出前保存原 `clientCommandId`。按当前语言的精确请求类型，使用 `getCommandReceipt` 或 `subscribeCommandReceipt` 查询同一命令的回执；已经取得 Message / Turn 身份时，继续查询原对象。

| 查到的事实 | 还需要做什么 |
|---|---|
| 命令已受理 | 使用真实返回的消息与轮次身份继续订阅 |
| Turn 已进入终态 | 再核对最终消息展示是否完整 |
| 结果仍未知，或当前历史只覆盖部分数据 | 保留原请求身份，继续按恢复合同核对 |

回执只说明对应命令的受理与关联状态，不保证任务成功，也不适用于所有云管理操作。完整规则见[处理错误与恢复](/domain-model/12-errors-examples)。

Runtime 是无影的执行环境模型。SDK 提供环境目录、云桌面基础管理、配置更新和服务访问入口；Agent、Conversation 与 Workspace 按各自接口使用真实环境作用域。

## 调用入口

| 要完成的事 | 当前公开入口 | 身份要求 |
|---|---|---|
| 查询和订阅环境目录、读取宿主能力 | `client.buildRuntimeManager`；Go 为 `BuildRuntimeManager` | 用户态 |
| 创建云桌面、等待创建完成 | 根 Client 的 `create` / `wait` | AK/SK 管理员态 |
| 开机、关机、重启 | 根 Client 的 `start` / `stop` / `reboot` | 用户态或 AK/SK 管理员态 |
| 重置系统 | 根 Client 的 `reset` | 两种身份均支持，镜像参数规则不同 |
| 释放云桌面 | 根 Client 的 `delete` | 仅 AK/SK 管理员态 |
| 执行系统命令、订阅命令结果 | RuntimeManager 的 `runCommand` / `subscribeCommand` | 管理员；Node / CLI 也支持 OAuth |

以上属于 Runtime 领域，但当前生命周期方法直接挂在根 Client 上。不能把它们写成 RuntimeManager.start。同一 RuntimeManager 工厂按根 Client 身份提供操作：管理员命令不会开启用户目录或 IM 链路。各操作仍由云端检查真实权限。

## 环境目录与能力

- [`listRuntimes`](/api-reference/runtimes/list)
- [`subscribeRuntimes`](/api-reference/runtimes/subscribe)
- [`getHostCapabilities`](/api-reference/runtimes/capabilities)

```ts
const runtimeManager = await client.buildRuntimeManager(ctx);
const { items: runtimes } = await runtimeManager.listRuntimes(ctx);
```

`listRuntimes` 返回 `items` 和 `nextCursor`，当前页中的每项都是 `Runtime`。认证或目录加载失败会报错，不当作空页；更多资源通过 [分页](/domain-model/page) 继续查询。`subscribeRuntimes` 仍订阅同一目录并携带同步状态，不自动选择第一项，也不把 IM 在线状态当成云桌面电源状态。

## 云桌面基础管理

`regionId` 和 `desktopId` 来自宿主已确认的真实云桌面资源信息。它们不能由 runtimeId、Agent ID 或显示名拼接得到。

| 操作 | 方法 | 关键差异 |
|---|---|---|
| 创建 | [`create`](/api-reference/client/create-desktops) | 仅管理员态；保留返回的桌面、订单与请求标识 |
| 等待创建 | [`wait`](/api-reference/client/wait) | 仅管理员态；用于创建等待，不是所有生命周期操作的通用等待器 |
| 开机 | [`start`](/api-reference/client/start) | 指定明确桌面 ID |
| 关机 | [`stop`](/api-reference/client/stop) | stoppedMode 仅管理员态可用；osUpdate 仅关机/重启接受 |
| 重启 | [`reboot`](/api-reference/client/reboot) | 返回受理信息，不证明已经重启完成 |
| 重置 | [`reset`](/api-reference/client/reset) | 用户态必须给 imageId；管理员态可省略，使用服务端默认行为 |
| 释放 | [`delete`](/api-reference/client/delete) | 仅管理员态；用户态调用返回 UNSUPPORTED |

开机的核心调用：

<CodeGroup>

```ts TypeScript
const receipt = await client.start(ctx, { regionId, desktopIds: [desktopId] });
```

```go Go
receipt, err := client.Start(ctx, &model.DesktopOperationRequest{
    RegionID: regionID, DesktopIDs: []string{desktopID},
})
```

```java Java
DesktopOperationRequest request = new DesktopOperationRequest();
request.regionId = regionId;
request.desktopIds = Collections.singletonList(desktopId);
DesktopOperationResponse receipt = client.start(request, ctx)
    .toCompletableFuture().get();
```

```sh CLI
wuying desktops start --request-file target.json
```

</CodeGroup>

以上为已初始化 Client 的核心调用，由宿主处理返回值、错误和关闭。CLI 的 target.json 只需包含目标字段，例如 `{"regionId":"cn-hangzhou","desktopIds":["desktop-id"]}`，其中 ID 必须替换为已确认的真实资源。完整请求与返回值见接口页。当前 JS/TypeScript、Go、服务端 Java 和 CLI 均有基础管理入口；Android/iOS 移动 JSON 清单没有对应入口。

### 重置的镜像与结果

用户态 `reset` 必须显式给出 imageId。管理员态可省略 imageId，SDK 不猜测或补查默认镜像；具体镜像由服务端决定。重置调用 RebuildDesktops，会初始化系统盘；替换镜像或数据盘的效果需按实际服务合同确认。

重置响应逐桌面返回 `results`，检查每项 `accepted` 与 `code`，不能把 HTTP 成功当成所有桌面均已受理。

### 受理与完成

基础管理返回 requestId；重置还返回逐桌面受理结果。这些都不保证资源已进入最终状态。超时或断线后保留原请求标识，先核对资源状态，不自动再次提交。

用户态基础操作可携带 `clientToken`；未传时 SDK 为本次调用生成一个。AK/SK 管理员态不接受此字段。共享请求 DTO 中的可选字段不表示所有操作都接受它们，不适用字段会在请求前拒绝。

## 远程脚本

通过同一 RuntimeManager 的 `runCommand` 执行系统脚本，使用 `subscribeCommand` 恢复结果订阅。最小代码、逐桌面事件及执行身份边界见[远程脚本](/domain-model/remote-script)。

## 配置与服务访问

同一用户态 RuntimeManager 还提供：

- [`updateAgentInstance`](/api-reference/runtimes/update-agent-instance)：更新公开配置。
- [`approveFotaUpdate`](/api-reference/runtimes/approve-fota-update)：请求固件升级。
- [`generateSceneUrl`](/api-reference/runtimes/generate-scene-url)：生成[端口服务](/domain-model/port-service)访问地址。

套餐和用量另见 [Credit](/domain-model/credit)。RuntimeManager 的资源侧查询入口与 CreditManager 的严格查询范围、默认值按各自接口使用。

## 标识与生命周期

Runtime 展示环境名称、状态与能力；RuntimeRef.runtimeId 作为会话查询的环境作用域。基础管理使用真实 desktopIds 和 regionId；实例、资源与计费标识不自动互转。

Client 统一管理身份与生命周期。订阅结束释放本地订阅；停止订阅或关闭 Client 不撤销云端已经接手的操作。

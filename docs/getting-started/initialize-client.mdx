先阅读[授权与认证](/integration/01-auth-and-lifecycle)，确定是服务端签名云 API，还是代表某个用户调用业务。服务端签名 Client 的初始化在认证指南中；本页说明**用户态 Client**，无论它运行在用户端还是代用户执行的后端。

## 1. 安装并准备配置

按[语言安装指南](/domain-model/language-bindings)安装同版本交付包，准备以下输入：

| 输入 | 来源和要求 |
|---|---|
| AuthCode | 由认证后端按已验证用户申请，在创建 Client 前获取新票，不复用旧票 |
| clientId | 平台授权管理员提供的接入标识，不是 AccessKey ID，也不是用户 ID |
| 数据位置 | Go / Java / Android / iOS 为当前身份独占的私有数据库文件；Node 为预先配置的私有持久化目录 |
| 登录地域 | 身份票据有地域要求时，通过 `loginRegionId`（Go：`LoginRegionID`）传入；不能拿资源地域或资源 ID 代替 |

浏览器需要真实 IndexedDB；Node 按 [Node 持久化配置](/sdk-reference/js#node-持久化)先安装 shim、保留补丁并完成初始化。下面的短例不代替这些运行环境准备。JS 示例服务于应用当前登录用户；不能用全局单例混接其他用户的凭据和数据。

## 2. 使用 AuthCode 创建 Client

下面只展示核心初始化语句。`authCode`、`clientId` 与数据文件来自上面的配置；Go 的 `dataFile` 是绝对文件路径字符串，Java 为 `Path`，Android / iOS 为应用私有目录中的绝对数据库文件路径字符串。CLI 由宿主注入对应环境变量。完整类型与可选项见[初始化接口](/api-reference/client/create)。

<ClientInitialization />

Go / Java / Android / iOS 的数据库父目录应为当前用户私有并预先准备，不能让不同账号、进程并发复用同一文件。JS 的持久化配置和账号隔离由应用按语言指南准备。需要指定登录地域时，按本语言的认证配置补充对应字段；Android / iOS 在上面的配置对象中增加 `loginRegionId`。

Android / iOS 在工作线程初始化和关闭；默认回调分别交付到主 Looper / 主队列。Android 使用配套双 AAR，最低 API 23；iOS 使用带 XCFramework 的 Swift Package，最低 iOS 13。安装与原生类型分别见 [Android](/sdk-reference/android) / [iOS](/sdk-reference/ios)。

## 3. 已有登录态时，使用完整组合

如果宿主已有当前用户的有效登录态，可以使用 `loginToken + sessionId + endUserId`，按需附带 `loginRegionId`，替代 AuthCode。**AuthCode、登录态和组织账号密码三条路径选择一种**，不同时填入两套凭据。

```ts TypeScript
import { Client } from '@aliyun/wuying-sdk';

const client = Client.create({
  loginToken, sessionId, endUserId,
}, { clientId });
```

| 语言 | 登录态字段 |
|---|---|
| TypeScript | `loginToken`、`sessionId`、`endUserId`、可选 `loginRegionId` |
| Go ClientOptions | `LoginToken`、`SessionID`、`EndUserID`、可选 `LoginRegionID` |
| Java ClientOptions.Builder | `loginToken(...)`、`sessionId(...)`、`endUserId(...)`、可选 `loginRegionId(...)` |
| Android / iOS 配置对象 | `loginToken`、`sessionId`、`endUserId`，可选 `loginRegionId`；替换 `authCode`，保留 `clientId` 和 `dataPath` |
| CLI 环境 | `WUYING_LOGIN_TOKEN`、`WUYING_SESSION_ID`、`WUYING_END_USER_ID`、可选 `WUYING_LOGIN_REGION_ID`；移除另一条路径的 AuthCode 配置 |

这些字段属于同一用户、同一登录上下文；不能拼接不同账号的票据，不能拿用户名显示文案或桌面 ID 代替。原始凭据只经宿主的安全链路注入，不输出到日志或公开示例。

## 4. 使用组织账号密码登录

JS / Go / Java 可由根 Client 接收当前无影用户的组织 ID、用户名和密码。以下变量由宿主安全注入；`organizationId` 是登录标识，不是 `officeSiteId`。先按上文配置 clientId 和私有数据位置。

<CodeGroup>

```ts TypeScript
const client = Client.create({ organizationId, username, password }, { clientId });
```

```go Go
client, err := wuying.NewClient(wuying.ClientOptions{
    OrganizationID: organizationID, Username: username, Password: password,
}, &config.UserConfig{ClientID: clientID, DataPath: dataFile})
```

```java Java
WuyingClient client = new WuyingClient(
    ClientOptions.builder().passwordAuthentication(organizationId, username, password).build(),
    SdkConfig.builder().clientId(clientId).dataPath(dataFile).build()
);
```

```sh CLI
secret-provider | wuying auth login --stdin
```

</CodeGroup>

CLI 中 `secret-provider` 代表宿主自己的秘密注入命令，其 stdout 提供包含 organizationId、username、password 的 JSON；它不是随 CLI 提供的命令。`auth login` 成功后只保存 LoginToken 登录组合，不保存密码；`auth import` 拒绝密码。也可用 `WUYING_CREDENTIALS` JSON 或完整的 `WUYING_ORGANIZATION_ID`、`WUYING_USERNAME`、`WUYING_PASSWORD` 环境组合进行本次调用，不持久化密码。

SDK 负责换票和续期，密码每个 Client 生命周期只提交一次，不自动重试。MFA、SSO、改密等挑战返回 `LOGIN_CHALLENGE_REQUIRED`（CLI 退出 4），当前版本不承接挑战流程；登录失败不覆盖 CLI 原有凭据。密码模式的登录端点仅接受 HTTPS。登录与后续调用使用同一获授权 clientId。Android / iOS 当前移动配置清单仍只支持 AuthCode 或 LoginToken。

## 5. 验证在线身份与授权

构造成功说明拿到了本地 Client 对象，不能证明在线认证或资源授权已通过。使用创建出的 Client，建立目录 Manager 并执行只读查询：

```ts TypeScript
const runtimeManager = await client.buildRuntimeManager(ctx);
const { items: runtimes, nextCursor } = await runtimeManager.listRuntimes(ctx);
```

返回当前身份下的一页 Runtime；通过 nextCursor 继续查询，见[列表查询与分页](/domain-model/page)。目录未加载或认证失败会报错，不返回伪造空页。查询成功不代表获得全部资源权限。Go、Java 和 Node 的完整初始化与只读验证源码见[代码示例](/examples/index)；Android / iOS 通过 `Client.request` 与 `Methods.runtimeSubscribeRuntimes` 订阅目录，见[移动端契约](/reference/mobile/contract)。

## 6. 结束或更换身份

应用持有并复用当前登录上下文的 Client，页面只释放自己的订阅；退出账号时退订后关闭 Client：JS `await client.close()`，Go `client.Close()`，Java `client.close()` 或 try-with-resources，Android `client.close()`，iOS `try client.close()`；移动端关闭放在工作线程。更换身份必须关闭旧 Client 并使用隔离数据位置；关闭本地连接不等于注销云端登录态或取消远端任务。

宿主负责提供初始身份、处理账号切换；SDK 管理已建立用户态的换票、续期和连接，不另起竞争的刷新器。JS 的 `updateLoginCredentials` 只适用于通过登录态初始化、且身份和登录地域不变的 Client，详见[语言指南](/sdk-reference/js)。

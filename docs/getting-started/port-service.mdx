这条流程把两项能力连起来：**管理员用远程脚本启动桌面内服务，无影用户通过端口服务访问它**。

## 准备

- 一台已开机的 Windows 云桌面，已安装可通过 `python.exe` 调用的 Python 3。
- 管理员 `admin` Client，以及能访问同一桌面的用户态 `client`。
- 桌面已配置指向 `127.0.0.1:8080` 的 **HTTP PortService Feature**，支持 GET / POST；8080 当前未被占用。
- 平台提供该 Feature 的真实 `featureId`，用于从返回结果中选择正确服务。

端口映射由平台预先配置；当前 SDK 通过 `generateSceneUrl` 获取已有配置的访问地址，不创建端口映射。若配置使用其它监听地址或端口，请同步修改下面的服务和配置；没有此 Feature 时先完成配置，不能仅启动脚本就推定能从外部访问。

下载[服务启动脚本](/downloads/examples/quickstart/start-echo-service.ps1.txt)，保存为 `start-echo-service.ps1`。脚本已包含演示服务的 Python 源码；[源码阅读入口](/downloads/examples/quickstart/echo-server.py.txt)供参考，无需额外上传文件。

先下载对应语言的等待函数：[Node run-script.mjs](/downloads/examples/quickstart/run-script.mjs.txt)、[Go run-script.go](/downloads/examples/quickstart/run-script.go.txt) 或 [Java RunScript.java](/downloads/examples/quickstart/RunScript.java.txt)，去掉下载后缀 `.txt` 并放在示例目录，Go 使用同一 package。它们是随文档提供的 demo helper，不是 SDK 内置方法；负责等待 completed、检查 allSucceeded、保存受理标识并释放本地订阅，不重发未知结果的脚本。

## 1. 用脚本启动服务

共享的 start-echo-service.ps1 将 Python 源码写入目标桌面，启动进程并验证本机响应。桌面 ID 与地域使用已确认的真实值。

## 2. 用户取得端口服务地址

各卡片使用已初始化的用户态 Client；取得目标服务地址后在同一用户的系统浏览器打开。`featureId` 是上面预配置服务的真实标识，不使用第一个不明用途的地址。

<DemoPortUrl />

地址有时效，不持久化或公开分享其中的授权参数。这里使用 Feature 返回的原始访问地址，不自行拼接主机名、端口或 token。如果返回的是授权/跳转入口，先在授权浏览器中完成进入服务的流程；不能把任意场景 URL 当作免鉴权的 HTTP API。

## 3. 完成一次消息交互

浏览器打开 **Wuying port demo** 页面后，在输入框中填写 `Hello Wuying`，点击 **Send**。

页面向当前服务地址发出 POST 请求，预期显示：

```json
{"reply":"Wuying: Hello Wuying"}
```

这条响应证明一次消息已通过端口服务到达桌面内的 Python 服务并返回。只取得 URL、本机端口探测成功或打开登录页，都不代表外部交互已经完成。服务页面使用同源请求，保留浏览器的实际授权上下文，不假设额外开放 CORS。

## 4. 清理

演示结束后用同一管理员脚本入口对保存的服务 PID 执行 `Stop-Process -Id <实际PID>`，核对后删除临时 `wuying-echo-demo.py`，再关闭各自的 Client。只关闭浏览器或 Client 不会自动停止 Python 服务。

示例使用 Python 标准库 HTTPServer 演示消息交互；正式服务按自己的部署和访问策略运行。完整接口见[端口服务](/domain-model/port-service)及 [`generateSceneUrl`](/api-reference/runtimes/generate-scene-url)。

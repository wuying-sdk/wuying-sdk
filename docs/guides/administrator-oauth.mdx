OAuth 是**管理员凭据的取得方式**，权限仍按 aliuid / RAM 身份裁决。它不增加第三类权限，也不会返回无影用户的 LoginToken。ASP 和 Agent 会话仍使用[用户态认证](/getting-started/initialize-client)。当前 OAuth / 动态 STS 接入仅覆盖 CLI 和 Node SDK；Go / Java 保留静态 AK/SK，Android / iOS 不保管管理员凭据。

## 使用 CLI 浏览器授权

准备阿里云 CLI 3.3.0 或以上版本，确认 `aliyun version` 可用。RAM 管理员需安装 official-cli OAuth 应用并分配允许访问的用户或角色，见[阿里云官方配置说明](https://help.aliyun.com/zh/cli/oauth-credentials)。在本机交互式终端执行：

```sh
wuying auth oauth --profile admin --aliyun-profile wuying-admin
```

`admin` 是无影 CLI profile，`wuying-admin` 是官方阿里云 profile；两者职责不同。命令通过 `aliyun configure --mode OAuth` 完成浏览器登录和授权，终端提示属于该交互流程，stdout 只输出最终 JSON。

复用已配置的官方 OAuth profile：

```sh
wuying auth oauth --profile admin --aliyun-profile wuying-admin --reuse
wuying auth status --profile admin
```

使用 `--no-input` 时必须同时指定 `--reuse`。无影不提供自己的设备码或回调地址输入参数；无浏览器的宿主先按官方 CLI 支持的方式准备 profile，再复用它。OAuth 凭据不得与其他管理员/用户凭据混用；环境凭据优先于保存的 profile，切换前移除冲突的环境输入。

`auth oauth` 成功只证明能解析凭据，不证明已经获得云桌面操作权限。已授权管理员可继续调用 `desktops`、`auth code`、`runtimes run-command` 和 `observe-command`，实际操作由云端校验。

## 凭据保存与退出

无影只保存 `aliyunOAuthProfile` 引用，不复制 OAuth access/refresh token。也可通过 `WUYING_ALIYUN_OAUTH_PROFILE`、`WUYING_CREDENTIALS` JSON 或 `auth import --stdin` 提供该引用。官方 Node credentials SDK 负责令牌和 STS 的获取、续期与官方配置持久化。

官方配置文件必须为当前用户拥有的私有普通文件；POSIX 权限要求为 0600。Wuying CLI 对官方配置加跨 profile 锁，因为续期会重写整个配置；不要同时运行其他会修改或刷新该配置的阿里云工具。OAuth 模式要求启动时未设置 NODE_DEBUG / NODE_DEBUG_NATIVE；CLI 会拒绝这两种可能输出凭据的 Node 调试模式。

`wuying auth logout --profile admin` 只删除无影 profile 的引用。删除官方本地令牌需明确执行 `aliyun configure delete --profile wuying-admin`；它不撤销 RAM 应用授权，见官方说明。退出、凭据到期或网络失败不授权重复提交资源写入。

## 在 Node 服务端提供可续期凭据

根 Client 接收 `credentialProvider`，每次管理员 RPC（包括状态/结果查询）都取得同一原子凭据快照：

```ts TypeScript
const admin = Client.create({
  credentialProvider: async (ctx) => credentialOwner.getCredentials(ctx),
});
```

`credentialOwner` 是宿主已有的凭据提供者，返回 `{ accessKeyID, accessKeySecret, securityToken? }`；不是 SDK 自带对象。Provider 独占凭据获取、缓存、刷新、并发控制和持久化；SDK 负责使用快照签名，不保存第二份令牌。此方式与静态 AK/SK、组织账号密码及用户票据互斥，浏览器拒绝管理员模式。

固定有效期的临时凭据也可一次性传入：

```ts TypeScript
const admin = Client.create({ accessKeyID, accessKeySecret, securityToken });
```

仅填临时 AK/SK 而遗漏所需的 securityToken 不能构成完整 STS 凭据。以上字段属于当前 Node 根 Client；不要推断旧 CloudClient、Go 或 Java 具有相同参数。

Provider 失败或返回空凭据时，业务请求尚未发送，返回 UNAUTHENTICATED；原始 provider 错误正文不回显。调用预算包含取凭据时间，取消后不发送迟到的业务请求；若 provider 忽略取消，宿主仍应等待其已有刷新结算再释放 owner。云 API 拒绝不会自动重发写入。CLI 已负责其官方 provider 的单飞、锁与退出前结算。

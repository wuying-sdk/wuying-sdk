使用 [ASP](/domain-model/asp) 查看并交互操作已授权桌面。它连接桌面画面，不创建 Agent 会话，也不执行脚本。需要已存在、可访问的桌面和无影**用户态**凭据；管理员 AK/SK / OAuth 不支持此入口。

## 打开指定桌面

先按[用户态初始化](/getting-started/initialize-client)准备 user profile，然后执行：

```sh
wuying asp open --profile user --desktop <desktopId> --region <regionId> --output jsonl
```

desktopId 和 regionId 必须来自已确认的云桌面资源，不用 Runtime ID 或显示名拼接。此命令不要求先运行 doctor 或 Agent/IM 目录查询。

系统浏览器打开后，在 60 秒内完成一次性页面交接，保持 CLI 进程运行。ASP 命令缺省生命周期为 1 小时；`--timeout` 可指定 1000–3600000 毫秒。该 profile 在此期间被锁定，其他同 profile 命令返回 PROFILE_BUSY；并行操作需独立认证的 profile。

浏览器打开不代表流化连接成功，以 AspManager 的 connected 状态为准。JSONL 的 asp-session 事件只返回本地 sessionId、resourceId、regionId 和状态；媒体与交互留在浏览器，不提供程序化截图或鼠标/键盘注入接口。

## 断开、刷新与恢复

点击 Disconnect、关闭页面或结束 CLI 会释放本地连接；不会关机、删除桌面或取消已经提交的 Agent 任务。最终 `status: closed` 表示播放器生命周期结束，不是业务任务完成。页面刷新不能复用一次性交接，结束旧会话后重新打开。

渲染器崩溃或生命周期连接丢失时，结果可能为 unknown，不假定已干净退出。凭据轮换期间异常终止可能需要重新登录；流化历史不持久化。

CLI 完成初始用户认证后关闭 Node Client，浏览器 Client 接管 ASP 和用户票据刷新。持久 profile 的新登录组合仍通过原 CLI 凭据文件保存；环境注入的临时凭据不持久化。密码和管理员密钥不交给播放器。旧 WebSDK 的 origin 内连接缓存会在启动/正常清理时移除；渲染器异常退出可能残留缓存，重新打开该 origin 或清理其站点数据后处理。

## 嵌入本地应用

普通用户使用上面的浏览器命令。已认证本地 GUI 适配器可通过继承的私有管道接收播放器地址：

```sh
wuying asp open --profile user --desktop <desktopId> --region <regionId> --viewer-fd 3 --embed-origin dsh-app://app
```

宿主必须实际创建 fd 3 私有管道；直接在普通终端执行这段命令不能代替管道准备。`--viewer-fd` 只接受 3，禁止系统浏览器自动启动，并向该管道发送一次 schemaVersion / type / sessionId / url 交接对象。

`--embed-origin` 必须是精确的 `dsh-app://app` 或 HTTP(S) loopback origin，且与 fd 3 同时使用。默认禁止 iframe 嵌入。放行静态播放器嵌入不取消 API 的 Origin/Bearer 检查，也不启用通用 CORS。

一次性 url 只在宿主 UI 内存使用，不进入 stdout、模型工具结果、对话或持久布局。宿主保持子进程与私有连接，断开只释放本地播放器。DeepSeek Harness 的现有接入见[插件指南](/guides/deepseek-harness)。

## 两类权限

Wuying SDK 目前按调用身份区分两类权限：**管理员权限**和**无影客户端用户态权限**。

| 权限分类 | 身份与权限范围 | 认证方式 |
|---|---|---|
| 管理员 | aliuid 维度的管理员身份，按对应 AK/SK 已获授权的范围操作资源 | 使用 AccessKey ID / Secret（AK/SK）签名 |
| 无影客户端用户态 | 无影用户体系中的当前用户，只能访问该用户获授权的资源与能力 | AuthCode、LoginToken 或组织账号密码，选择其中一种 |

管理员与用户态的区别取决于调用身份。服务端使用用户凭据代用户调用时，仍属于用户态权限，不构成第三类权限。

### 用户态的三种认证方式

- **AuthCode**：通过已授权的认证后端为当前无影用户获取授权码，再初始化用户态 Client。
- **LoginToken**：使用当前无影用户已有的有效登录态。SDK 初始化需同时提供 `loginToken`、`sessionId`、`endUserId`，按需提供 `loginRegionId`；其中 LoginToken 对应 SDK 参数名 `loginToken`。

- **组织账号密码**：JS / Go / Java 根 Client 接收 `organizationId`、`username`、`password`，由 SDK 换取 LoginToken 并管理续期。组织 ID 是登录标识，不是办公网络 ID。CLI 使用 `auth login --stdin`；Android / iOS 当前移动配置清单未开放此方式。

**认证**确认当前身份；**授权**决定该身份可以访问哪些资源、执行哪些操作。取得 AuthCode 或 LoginToken 不会扩大用户权限，构造 Client 成功也不代表资源授权已通过。`clientId` 是应用接入标识，不能替代 AK/SK、用户身份或资源授权。

## 通过 AuthCode 接入用户态

1. 业务后端验证自己系统中的当前用户，并确认其租户、无影用户映射和允许访问的资源。
2. 后端按已获授权的云 API 申请该用户的 AuthCode；AK/SK 保留在服务端。
3. 用户端通过已认证的业务链路取得票据，在内存中初始化用户态 Client。业务系统自己的取票接口由接入方实现，不是 SDK 内置 HTTP 接口。
4. SDK 完成用户态换票、连接与后续业务调用；各操作仍由服务端检查权限。

用户 ID、目标资源和票据限制策略由后端按已验证身份决定，不能直接相信前端提交的任意用户 ID 或放宽权限的策略。AuthCode 的限制策略与 RAM 策略属于不同层次，按对应产品接口支持的格式配置。

## 服务端：初始化签名 Client 并申请用户票据

下面展示 **Node.js、Go、Java 服务端**的核心调用。AK/SK 来自受信任服务端配置，`authorizedEndUserId` 已由业务后端核验并映射。管理员 Client 用于签名云管理请求，可通过 RuntimeManager 执行管理员命令；用户目录等操作仍需独立用户态 Client；用户票据交给独立的用户态 Client。

<CodeGroup>

```ts Node.js / TypeScript
import { Client } from '@aliyun/wuying-sdk';

const admin = Client.create({ accessKeyID, accessKeySecret });
const ticket = await admin.getAuthCode(ctx, {
  endUserId: authorizedEndUserId,
});
```

```go Go
admin, err := wuying.NewClient(wuying.ClientOptions{
    AccessKeyID: accessKeyID, AccessKeySecret: accessKeySecret,
}, nil)
if err != nil {
    return err
}
ticket, err := admin.GetAuthCode(ctx, &model.GetAuthCodeRequest{
    EndUserID: authorizedEndUserID,
})
```

```java Java
WuyingClient admin = new WuyingClient(
    ClientOptions.builder().accessKey(accessKeyId, accessKeySecret).build()
);
GetAuthCodeParams request = new GetAuthCodeParams();
request.endUserId = authorizedEndUserId;
GetAuthCodeResponse ticket = admin.getAuthCode(request, ctx)
    .toCompletableFuture().get();
```

</CodeGroup>

以上为核心语句；宿主负责错误处理及在服务退出时关闭自己持有的 Client。完整请求、端点配置和返回值见[获取票据](/api-reference/client/get-auth-code)。AK/SK 模式不建立用户数据库或 IM 连接，不能与用户票据混合初始化。

执行上述代码会真实申请票据，可能使同一用户此前取得的 AuthCode 失效。示例使用已存在的无影用户，不自动创建用户；需要按资源进一步限制票据时，在后端按实际产品支持的 `policy` 参数构造，不能照搬为任意资源通用策略。不要向客户端提供可代任意用户签发票据的开放接口。

服务端的 API endpoint、允许的身份映射及所需 RAM Action 以实际产品和部署配置为准。关于本示例调用的 AppStream `GetAuthCode`，参阅[官方接口说明](https://help.aliyun.com/zh/wuying-appstreaming/developer-reference/api-appstream-center-2021-02-18-getauthcode)；其云 API 使用 RPC 签名，账号准备见[官方 API 概览](https://help.aliyun.com/zh/wuying-appstreaming/developer-reference/api-appstream-center-2021-02-18-overview)。不同无影产品的授权码规则需分别核对。

## 当前各语言的入口差异

| 接入方式 | 签名云 API / 获取 AuthCode | 初始化用户态 Client |
|---|---|---|
| JS / TypeScript | `Client.create({accessKeyID,accessKeySecret})`、`admin.getAuthCode` | `Client.create` |
| Java | `new WuyingClient` 的 AK/SK 模式、`admin.getAuthCode` | `new WuyingClient` |
| Go | `wuying.NewClient` 的 AK/SK 模式、`admin.GetAuthCode` | `wuying.NewClient` |
| CLI | 通过环境或已配置的管理员 profile 提供 AK/SK；`wuying auth code` 获取 AuthCode | 从环境或用户 profile 建立用户连接 |
| Android / iOS | 通过受信任后端取用户票据，不在应用内保管 AK/SK | AndroidClient.connect / GoEngine 与原生 Client |

CLI 管理员凭据由宿主注入 `WUYING_ACCESS_KEY_ID` / `WUYING_ACCESS_KEY_SECRET`，或使用 `WUYING_CREDENTIALS` JSON。显式 JSON 优先于独立环境变量，环境优先于 profile；管理员凭据与用户凭据不能混用。切换 profile 不会覆盖当前环境中的凭据，详见 [CLI 指南](/sdk-reference/cli)。

本版本 `CloudClientOptions` 未提供通用的临时凭据 `securityToken` / Credential Provider 参数，不能仅填临时 AK/SK 就宣称支持 STS 凭据链。采用 RAM 角色或 STS 时，先按相应云 API SDK 的实际支持配置服务端调用，再将用户票据交给用户态 Client。

## 高级传输入口

全量清单还列出 Java 管理员 IM、公开传输门面和 Go 移动桥接等协议宿主入口。它们不是上述两类权限之外的第三类业务权限；协议凭据的使用边界按各自公开合同核对。

- 本版本 Java 管理员 IM 使用 `AdminTokenProvider` 提供当前管理员 token，按操作或订阅握手获取。Provider 只提供凭据，不授予或推断管理权限；服务端仍校验真实权限。管理员身份变更需要隔离游标命名空间，不能把 `cursorNamespace` 当作授权凭据。
- 公开传输门面面向协议宿主。普通应用通过根 Client / Manager 使用业务能力；高级宿主按原生接口配置身份、传输和存储，不借此绕过授权或复制另一套会话事实。

完整配置、重载和回调合同分别见 [Java 公开清单](/reference/java/public)与 [Go 公开清单](/reference/go/public)。不要将管理员 token 下发到普通用户端。

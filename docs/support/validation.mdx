每种语言先按自己的安装指南运行默认帮助或离线检查。交付制品存在、跨平台构建完成、类型检查通过，都不能替代目标平台和真实服务验证。

## 推荐验证顺序

1. 核对制品哈希、SDK 源码基线、语言版本与 OS / CPU。
2. 安装依赖，运行同语言示例的默认 `--help` 或离线检查，不注入业务凭据。
3. 由宿主安全注入认证材料和账号独占数据位置，完成真实只读 Runtime / Agent 查询。
4. 明确选定授权环境，为受控测试分别保存稳定建会和消息请求身份，显式执行一次建会与发送。
5. 分别确认受理、权威 Turn 终态、最终展示完整性，以及刷新或重新打开后的历史。
6. 按实际使用范围验证附件、审批 / 问答、取消、断线恢复和账号切换。

只读成功只证明该身份和该链路的结果。没有执行的真实服务、审批、任务或目标平台检查，应记录为未执行。

## 示例与配套文件

本站的示例链接提供原交付源码的纯文本视图，便于核对接线。实际编译和运行请使用维护团队提供的完整同语言交付包，保留其目录、依赖和安装补丁；零散文本视图不是独立可安装 SDK。

不要把完整 Shell demo、历史 fixture、浏览器页面可见功能或私有扩展，当作所有 SDK 都已公开的业务接口。具体边界见[语言绑定](/domain-model/language-bindings)和[错误与运维](/integration/04-errors-and-operations)。
